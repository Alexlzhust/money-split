# Agent Handoff Notes

## Project

This is a single-page multi-party expense splitter.

Current production URL:

- https://multi-party-expense-splitter.vercel.app

The app lets users:

- Add custom members.
- Add equal or custom split transactions.
- See transaction details.
- See net balances and simplified settlement transfers.
- Undo the latest transaction.
- Edit or delete any transaction.

## Tech Stack

- Static browser app with React loaded through ESM import maps in `index.html`.
- `htm` is used instead of JSX, so components use template literals.
- Tailwind CSS is compiled locally into `dist/styles.css`.
- Vercel Functions under `api/`.
- Neon Postgres through `@neondatabase/serverless`.
- Node built-in test runner for tests.

There is no Vite build step. Do not add one unless you intentionally migrate the app structure.

## Data Model

Tables are created automatically on first API access in `api/_database.js`.

Tables:

- `members`
  - `name` primary key
  - `created_at`
- `transactions`
  - `id` primary key
  - `title`
  - `total_amount_cents`
  - `payer_name`
  - `split_type`
  - `created_at`
- `splits`
  - `transaction_id`
  - `user_name`
  - `amount_cents`

Money is stored as integer cents in Postgres and converted at the API boundary.

Schema setup uses a Postgres advisory lock:

```sql
pg_advisory_lock(hashtext('multi-party-expense-splitter-schema'))
```

Keep that lock. It prevents concurrent Vercel cold starts from racing during `CREATE TABLE IF NOT EXISTS`.

## API Routes

`GET /api/state`

- Returns `{ users, transactions }`.

`POST /api/members`

- Body: `{ "name": "Alice" }`
- Adds a member if not already present.

`POST /api/transactions`

- Body: `{ "transaction": { ... } }`
- Adds a transaction.

`PUT /api/transactions`

- Body: `{ "transaction": { ... } }`
- Updates a transaction and rewrites its splits.

`DELETE /api/transactions`

- Body: `{ "id": "transaction-id" }`
- Deletes a transaction.

`POST /api/reset`

- Deletes all members, transactions, and splits.
- This is currently exposed and used by the UI reset button, so treat it carefully if adding authentication later.

## Frontend Structure

Top-level state:

- `src/App.js`
  - Loads remote state with `fetchRemoteState()`.
  - Falls back to localStorage mode if API/database is unavailable.
  - Owns edit state via `editingTransaction`.
  - Routes add/update/delete/reset actions to remote API or local helpers.

Components:

- `src/components/MemberManagement.js`
  - Custom member name input.
- `src/components/TransactionForm.js`
  - Add/edit form.
  - Equal and custom split modes.
  - Custom split total validation.
- `src/components/TransactionList.js`
  - Transaction cards.
  - Undo latest, edit, and delete controls.
- `src/components/SettlementDashboard.js`
  - Net balances and simplified transfer paths.

Core utilities:

- `src/utils/settlements.js`
  - Currency rounding.
  - Equal splits.
  - Net balances.
  - Simplified debts.
- `src/utils/transactionState.js`
  - Local add/update/delete/latest transaction helpers.
- `src/server/statePayload.js`
  - Maps database rows to app state.
  - Normalizes incoming transactions to cents.

## Design Notes

- Keep the app lightweight; it is meant as a quick personal finance tool.
- Avoid landing-page/marketing UI. The first screen should remain the tool itself.
- UI is operational and compact: forms, dashboard, and list.
- Use lucide icons for action buttons.
- Avoid nested cards and large decorative layouts.
- Maintain responsive behavior with Tailwind utilities.

## Known Constraints

- There is no authentication. Anyone with access to the production URL can mutate shared data.
- The reset endpoint is public.
- Member names are primary keys, so renaming members is not currently implemented.
- Deleting a member is not currently implemented.
- Local `npm run dev` serves only static files. API/database behavior is available on Vercel, or with Vercel local development once Vercel auth/env is configured.

## If Taking Over

Recommended first steps:

1. Run `npm test`.
2. Run `npm run build`.
3. Open the production URL and check `/api/state`.
4. If changing database behavior, test against production or a separate preview database, then reset test data.
5. Keep `.env.local` private.
